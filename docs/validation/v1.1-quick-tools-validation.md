# 1.1 随手工具验证记录

2026-10-22，开发分支 `codex/v1.1-toolbox-entry`。Q01–Q04 接入原生 App；用户确认只参考 iOS 截图的大数字与操作方式，界面沿用米白底、酒红主题。工程配置保持 1.0.1（4），既有视频分析按原进度保留。

## 实现与边界

| 工具 | 当前实现 |
| --- | --- |
| 秒表 | 大数字、启动／停止／继续、分段、复位；当前状态和分段本机保存，后台／重启后根据参考时间恢复 |
| 倒计时 | 时／分／秒滚轮、常用时长、进度圆环、暂停／继续／取消／再次开始；截止时间本机保存；系统本机通知提醒 |
| 战术白板 | 手机／iPad 进入时请求横屏、离开恢复方向；棒球场矢量底图、四色手绘、九个防守位置及三个垒上跑者、拖动／移除、撤销／重做／清空／新建；草稿接入记录；1600×1000 图片保存相册 |
| 测距 | ARKit 表面射线检测、准星选起点／终点、三维距离与线段、米／厘米切换、重测、结果主动保存到记录；相机权限及追踪／中断状态 |

秒表与倒计时保存当前状态，暂不建立每次训练的独立历史。白板与测距使用本机 JSON 文件接入统一记录，保留视频 SwiftData 模型和快照格式。写入使用原子替换；读取失败保留原文件；数据目录排除系统备份。

倒计时后台提醒依赖用户授权及系统通知设置，未授权时显示状态。每次运行使用独立 ID，暂停／取消会撤回对应提醒，迟到的异步回调不会误删新运行的提醒。计时按参考时间计算，不靠后台定时器累加。相册只申请添加照片权限。

AR 测距使用 [Apple ARWorldTrackingConfiguration](https://developer.apple.com/documentation/arkit/arworldtrackingconfiguration) 与 [raycastQuery](https://developer.apple.com/documentation/arkit/arframe/raycastquery(from:allowing:alignment:))，没有打开或嵌入系统“测距”App。模拟器明确显示不支持，不展示虚构测量。实景端点、环境追踪与距离误差仍需支持 ARKit 的设备验证，当前显示“AR 估算距离 · 请复核”。

白板采用 [UIWindowScene.requestGeometryUpdate](https://developer.apple.com/documentation/uikit/uiwindowscene/requestgeometryupdate(_:errorhandler:))。iPad 支持可调整窗口时系统可能忽略方向请求，因此操作层在竖向窗口内也自动旋转为横向；系统允许横向窗口时直接使用窗口方向。保持原 App 的多任务支持；方向限制依据 [Apple supportedInterfaceOrientations](https://developer.apple.com/documentation/uikit/uiviewcontroller/supportedinterfaceorientations)。结束提醒采用 [UNTimeIntervalNotificationTrigger](https://developer.apple.com/documentation/usernotifications/untimeintervalnotificationtrigger)。

## 检查与证据

环境：iOS 26.1，项目专用 iPhone 16e 与 iPad mini（A17 Pro）模拟器。结果保存在忽略目录 `artifacts/v1.1-quick-tools/`。

- `QuickToolsTests` 八项：计时分段／暂停恢复／截止与零值、绘制和移动的撤销重做、保存重开／联合筛选／独立删除、损坏文件保护、三维距离／无效端点、白板图片渲染。
- `ToolboxTests` 三项：旧视频／对比只读兼容、删除后摘要安全、场景筛选一致性。
- `QuickToolsUITests` 四项：秒表分段／后台返回／停止／重启／复位；倒计时设置／暂停继续／取消／到时；白板自动横屏／手绘／撤销重做／跑者拖动／相册保存／记录重开删除；模拟器测距不可用提示。
- 原入口 UI 两项：倒品字首页／场景导航、原视频记录筛选／返回／删除。

| 结果包 | 通过／失败／跳过 | 说明 |
| --- | --- | --- |
| `final/iphone/V1.xcresult` | 17／0／0 | 核心、计时、原入口及白板完整流程 |
| `final/ipad/V1.xcresult` | 16／1／0 | 当时的失败为程序横屏布局检查；其余通过，随后补充 iPad 窗口适配 |
| `whiteboard-final/iphone/V1.xcresult` | 1／0／0 | 横屏适配后的白板完整流程 |
| `whiteboard-final/ipad/V1.xcresult` | 1／0／0 | 同上，进入即为横向操作层，未先改变测试设备方向 |
| `presentation-final/iphone/V1.xcresult` | 1／0／0 | 固定工具栏高度后的完整白板流程与屏幕截图 |
| `presentation-final/ipad/V1.xcresult` | 1／0／0 | 同上，iPad 布局、拖动、相册保存及记录重开通过 |

球场工具栏固定为 52pt，避免横向滚动栏占用过多球场空间。按每项用例的最新适用结果统计，两端各 17 项均有通过证据，共 34 项，无未解决的失败；前述 iPad 失败结果保留，修复后白板专项及最终布局专项均在双端通过。原始汇总见本机 `artifacts/v1.1-quick-tools/summary.json`。

核心预检 `core/{iphone,ipad}/V1.xcresult` 两端各 11 项通过。面向真实 iOS SDK 的未签名通用设备编译成功，见 `device-final-build.log`；这是代码及框架连接验证，不代表真实测距验收，也不是签名归档或分发包。

## 迭代记录

用户后续指出白板顶部空白过大：场景导航在外层统一强制显示系统导航栏，与白板自己的返回／工具栏重复占位。已按白板路由在外层隐藏系统导航栏；新增导航栏不可见检查，并重跑白板完整流程与场景返回检查，两端各 2 项通过、0 失败，结果保存在 `whiteboard-spacing/{iphone,ipad}/V1.xcresult`。新截图确认工具栏贴近顶部、球场获得额外高度；手机预览为 `artifacts/design/v1.1-quick-tools/iphone-tactics-spacing.png`。

## 保留的未验证项

- 支持 ARKit 的真实设备上，实景端点、环境追踪与不同距离／光线下的实际误差。
- 真机锁屏、静音／专注模式下的通知与声音表现；采用标准本机通知，未承诺闹钟式持续响铃。
- iPad 多任务窗口中的系统方向限制；本轮 UI 验证为专用模拟器全屏。
- 原视频完整性能对照及长时资源验收继续按此前安排留待人工测试。
